# Wellness Mobile Spa - Project Documentation

Welcome to the Wellness Mobile Spa project! This document provides a comprehensive overview of the project's architecture, technology stack, and development workflows to help you get up to speed quickly.

---

## 🌿 Project Overview

Wellness Mobile Spa is a professional mobile spa service based in Cape Town, offering a range of wellness treatments delivered directly to the client's location (Home, Hotel, Airbnb, or Office).

### Key Features
- **Service Catalog**: Browse various spa treatments, corporate wellness programs, and special occasion packages.
- **Booking Flow**: A simplified "How to Book" process where users can select services and initiate contact.
- **Gift Vouchers**: Purchase and redemption system for gift vouchers with integrated payment processing.
- **Interactive UI**: Modern, responsive design using a "Bottom Sheet" pattern for deep-dive content.
- **Admin Notifications**: Automated email alerts for contact inquiries and voucher transactions.

## 🛠 Technology Stack

### Frontend
- **Framework**: React 19 (Vite-based)
- **Language**: TypeScript / JavaScript (JSX/TSX mix)
- **Styling**: Vanilla CSS (Global variables, Mixins, and Scoped CSS)
- **Animations**: Framer Motion, React Intersection Observer
- **Components**: 
  - `react-slick` & `slick-carousel` for sliders.
  - `react-calendar` for date selection.
- **Deployment**: GitHub Pages

### Backend
- **Runtime**: Node.js (Express)
- **Database**: SQLite (via `sqlite` and `sqlite3` packages)
- **Payment Gateway**: Yoco (Checkout redirect flow)
- **Email Service**: Nodemailer (via Gmail or custom SMTP)
- **Utilities**: `uuid`, `dotenv`, `node-fetch`

## 🔄 Core Workflows

### 1. Booking State Management
The project uses a centralized state in `App.jsx` to manage selected services. 
- `selectedServices`: An array of service objects chosen by the user.
- `sheetContent`: Controls which component is currently rendered inside the `BottomSheet`.

### 2. The Bottom Sheet Pattern
Instead of traditional routing, the app uses a `BottomSheet` component to display detailed information (About Us, Services, Price List, etc.).
- **Trigger**: Buttons or links call `openSheet(title, Component, props)`.
- **Close**: Clicking the backdrop or a close button resets the `sheetContent` state.

### 3. Voucher Purchase & Redemption
The backend handles the entire lifecycle of a voucher:
1. **Creation**: `POST /api/create-voucher` generates a record and a Yoco checkout link.
2. **Payment**: User pays on Yoco; Yoco redirects to `GET /api/payment-success`.
3. **Issuance**: Backend verifies payment via Yoco API, marks voucher as `issued`, and emails the recipient.
4. **Redemption**: `POST /api/redeem-voucher` validates the code and notifies the admin.

## 🚀 Getting Started

### Prerequisites
- Node.js (v18+)
- npm

### Installation
1. Clone the repository.
2. Install frontend dependencies: `npm install`
3. Install backend dependencies: `cd backend && npm install`

### Development
1. **Start Frontend**: `npm run dev` (Runs on `http://localhost:5173`)
2. **Start Backend**: `cd backend && npm start` (Runs on `http://localhost:3000`)

### Environment Variables (`backend/.env`)
Create a `.env` file in the `backend/` folder:
```env
YOCO_SECRET=your_yoco_secret_key
EMAIL_USER=your_email@gmail.com
EMAIL_PASS=your_app_password
BASE_URL=http://localhost:3000
ADMIN_EMAIL=admin@wellnesmobilespa.co.za
```

## 📡 API Endpoints (Backend)

| Method | Endpoint | Description |
| :--- | :--- | :--- |
| `POST` | `/api/create-voucher` | Create pending voucher and get Yoco URL |
| `GET` | `/api/payment-success` | Yoco success callback (verifies payment) |
| `GET` | `/api/voucher-status/:id`| Fetch voucher details |
| `POST` | `/api/redeem-voucher` | Mark a voucher as used |
| `POST` | `/api/contact` | Send contact form email |
| `POST` | `/api/test-email` | Smoke test email configuration |

Since you are running your server on localhost, Yoco's servers cannot "see" or "reach" your computer. Here is how ngrok solves that:

  1. Enabling Yoco Redirects (The "Success URL")
  In backend/server.js, the code constructs a successUrl that it sends to Yoco:

   1 const successUrl = `${BASE_URL}/api/payment-success?voucher_id=${voucher_id}`;
  If BASE_URL is localhost:3000, Yoco will try to redirect the customer's browser to a location that only exists on your machine. If you are testing on a different device or if Yoco needs to
  verify the URL, it will fail. ngrok provides a public URL (like https://xyz.ngrok-free.app) that tunnels directly to your local port 3000, allowing the redirect to work perfectly.

  2. Testing the Voucher Lifecycle
  The project uses a "Payment Confirmation via Redirect" strategy. For the backend to automatically mark a voucher as "Issued" and send the email, the GET /api/payment-success endpoint must be
  triggered. 
   - Without ngrok: You would have to manually type the success URL into your browser to simulate a successful payment.
   - With ngrok: The actual Yoco checkout flow can redirect back to your local code, allowing you to test the full automated loop (Payment -> DB Update -> Email Sent) in real-time.

  3. Mobile Testing
  Because this is a Mobile Spa application, you likely want to see how the "Bottom Sheet" and UI feel on an actual iPhone or Android device.
   - By running ngrok, you can open the generated public URL on your physical phone’s browser while your laptop is still running the code.

  4. How to use it with this project:
   1. Start ngrok: Run ngrok http 3000 in your terminal.
   2. Update .env: Copy the Forwarding URL provided by ngrok and paste it into backend/.env:

   1     BASE_URL=https://your-unique-id.ngrok-free.app
   3. Restart Backend: The server will now use that public URL for all payment links.

  In short, ngrok makes your laptop behave like a live web server, which is essential for testing any third-party integration like payments or webhooks.
